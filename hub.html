Projects / PROJ-2PX3-HUB

Centralized Learning Hub

Engineering design processStakeholder analysis Technical writingENGINEER 2PX3

1.0The Problem

McMaster uses a variety of different virtual methods to communicate and manage classes. Each class implements these differently, setting unique expectations, and students are required to navigate these inconsistent structures. This can lead to confusion and reduced efficiency in the rigorous academic environment. The goal of the project is to create a consistent learning solution for class needs that is cost effective, easy to use and accessible to as many students as possible.

2.0Design Process

Unlike other projects, the deliverable here was the process itself, the main goal was to take into account stakeholder needs to create an ideal solution

  1. Stakeholder analysis — identifying students, instructors, TAs, and IT administration; mapping each group's needs and where they conflict.
  2. Requirements definition — translating those needs into concrete objectives, constraints, and evaluation criteria.
  3. Concept generation — structured brainstorming across solution approaches, captured in comparison tables.
  4. Evaluation & selection — scoring concepts against the criteria to converge on the centralized-hub design.
  5. Communication — a formal presentation and final report documenting the full rationale chain from problem to proposed design.

3.0What I Took Away

The value of this project was learning to defend design decisions with a traceable rationale: every feature in the final concept maps back to a stakeholder need through an explicit requirement. The skill of rationalization carries directly into technical work, where a spec-first mindset is what separates a design from a prototype.
